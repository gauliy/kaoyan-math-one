# 学习记录协议

## 定位与执行

脚本 `scripts/learning_store.py` 仅依赖 Python 3 标准库。Windows 可用 `py -3 -X utf8`。命令中的脚本路径须为实际技能绝对路径，输入 JSON 用 UTF-8 文件传入，避免把公式或用户文字拼成 shell 命令。

默认学习目录为 `~/Documents/Codex/math-one-learning`，固定设置位于 `${CODEX_HOME 或 ~/.codex}/kaoyan-math-one-settings.json`。首次使用时初始化；安装技能本身不会建立或迁移学习档案。`--root` 优先于固定设置，只影响本次调用；运行 `--root <目录> init --set-default` 才记住新目录。用户要求迁移目录时先复制并检查完整旧档案，再设置新目录；不能只建立空目录并声称旧记录已迁移。不要修改 HOME 或 CODEX_HOME。

`learning.sqlite3` 是权威档案，含全部版本；`学习总览.md` 和 `views/<类型>/<编号>.md` 为自动生成的中文可读视图。`sources/` 保存原始来源与附件。不要直接编辑视图来更新记录；用脚本保存后自动刷新，可用 `export` 恢复视图。备份整个学习目录和固定设置。

每次运行 `status` 得到本地日期、个人设置、到期复测索引与计数。然后 `list --topic <知识点>` 或 `list --kind problem --date YYYY-MM-DD` 按需定位，用 `get` 取详情。读取失败不会自动建空档案；首次使用明确 `init --set-default`。状态只读取索引，不输出训练答案。

```text
py -3 -X utf8 <技能绝对路径>/scripts/learning_store.py status
py -3 -X utf8 <脚本> list --kind problem --topic 泰勒
py -3 -X utf8 <脚本> get problem <题目编号>
py -3 -X utf8 <脚本> list --kind problem --since 2026-10-12 --until 2026-10-18
py -3 -X utf8 <脚本> list --due 2026-10-14
py -3 -X utf8 <脚本> put problem <唯一编号> --file <输入JSON文件> --expected-revision 0 --reason 首次记录
py -3 -X utf8 <脚本> append-attempt <题目编号> --file <作答JSON文件> --expected-revision <刚读取的版本>
py -3 -X utf8 <脚本> history weakness <编号>
py -3 -X utf8 <脚本> check
```

新增期望版本为0；修改时先读当前版本再传 `--expected-revision` 和具体 `--reason`。版本冲突时重读、合并，不覆盖其他会话新增信息。每次成功写入保留旧版本；题目更新不能移除旧作答编号。修改旧作答须注明修正与原因，不伪装成当时结果。

一次教学可能写多条关联记录：先题目，再薄弱点、卡、复测；每个操作均单独验证成功。发生部分失败时如实报告实际成功项和未保存项，不说整组全成功。题目与薄弱点编号必须指向已存在记录。

## 数据结构

所有内容使用中文键名；类型和编号为内部技术标识。所有记录须有非空 `标题`，日期用 YYYY-MM-DD，未知事实用 null；题目原题号只作为来源字段，不当作唯一编号。

| 类型 | 必需内容与推荐补充 |
| --- | --- |
| profile | `标题`、`时区`；考试年份、复习阶段、主要教材、目标、每天可用分钟、讲解模式、首次设置已询问。固定编号 learner |
| problem | `标题`、`题目`、`学习状态`、`作答`；学习日期、原题号、来源、题目核实状态、关键条件、已表现能力、卡点、知识点、关键解法、正确结果、解答核实、诊断依据。缺原件时说明来源 |
| weakness | `标题`、`诊断状态`、`掌握状态`、`证据`；题目编号列表、知识点、错误类别、前置能力、状态依据、撤销原因 |
| card | `标题`、`识别信号`、`关键动作`、`适用条件`、`个人易错点`、`回忆问题`；题目编号列表、薄弱点编号列表 |
| review | `标题`、`到期日期`、`状态`、`目的`；题目编号列表、薄弱点编号列表、复测类型、题目来源、复测题、参考解答、验算说明、安排依据、结果。复测状态：待复测/已完成/已取消 |
| summary | `标题`、`类型`（每日/阶段）、`范围开始`、`范围结束`、`正文`；日期、题目编号列表、证据限制、下一步 |
| correction | `标题`、`原结论`、`修正`、`依据`；日期、题目编号列表、薄弱点编号列表、受影响安排 |

`题目编号`、`薄弱点编号`均为列表。引用编号必须存在。不要从枚举状态自行推断升级，判断依据见 [训练与复盘](review.md)。脚本只检查结构、关联和版本，数学正确性与证据充分性仍由辅导者核实。

每次作答必需 `编号`、`日期`、`状态`、`提示`、`证据来源`；推荐记录作答内容、正确步骤、卡点、是否独立、是否看过答案、复测类型、对应复测编号、结果。作答日期是实际学习日期，导入的写入时间自动另存。历史记录中的“旧助手描述”不能写成学生原始作答。

新题示例输入（字段根据实际题目填写，不创建虚假示例作答）：

```json
{
  "标题": "题目简述",
  "题目": "可靠转写；不确定条件另注明",
  "学习日期": "2026-10-13",
  "学习状态": "未作答",
  "作答": [],
  "来源": "用户拍照",
  "题目核实状态": "待核实",
  "知识点": ["实际考查知识点"]
}
```

## 可读与持久性

写入成功后用 `get` 核对相关记录，必要时运行 `check`。若数据库保存成功而视图生成失败，输出会明确标记：仅称数据库已保存，修复后运行 export。数据库打不开或无访问权限时，告知哪些未保存，并继续可做的讲解；不在其他位置悄悄建立第二个档案。

用户想查看时可打开学习总览或相关视图。对外导出到当前对话 outputs/，保留学习目录为长期权威来源。跨设备需要用户可访问的同步或迁移，本技能不承诺自动同步。
